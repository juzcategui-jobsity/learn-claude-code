## Naming Pattern

Every top-level heading follows a consistent three-part structure:

```
# s{NN}: {Topic} — {Pithy Principle}
```

1. **`s{NN}:`** — A zero-padded two-digit section number that matches the folder prefix, acting as a stable identifier.
2. **`{Topic}`** — A short PascalCase or Title Case name for the core concept introduced in that section (e.g., *The Agent Loop*, *Tool Use*, *Permission*, *Hooks*, *TodoWrite*). This also matches the folder's suffix.
3. **`— {Pithy Principle}`** — A memorable, opinionated one-liner after an em-dash that captures *why* the concept matters (e.g., *"One Loop Is All You Need"*, *"Add a Tool, Add Just One Line"*).

In short: **number → concept name → memorable motto**, making each heading both navigable (by number) and self-explanatory (by the motto) at a glance.

## s06: Subagent — Give a Subtask Its Own Context

### The Problem
When an agent works on a complex task (e.g., tracing a bug through many files), every intermediate tool call and result accumulates in `messages[]`, bloating the context with details that are no longer needed once the sub-task is done.

### The Solution
Introduce a `task` tool that spins up a **nested agent loop** with a **fresh `messages[]`**. The subagent does its work independently, and only its final text is returned to the parent — all intermediate steps stay isolated and never pollute the parent's context.

### Key Design Decisions
| Aspect | Choice |
|---|---|
| Conversation | Fresh `messages[]` — parent history not shared |
| Execution | Same Python process and `WORKDIR` — filesystem is shared |
| Return value | Final text only — child tool calls never enter parent messages |
| Delegation depth | No `task` tool in subagent — only one level of nesting |
| Permissions | Shared hooks — same checks apply to both parent and subagent |

### How It Works
- `run_subagent(prompt)` builds its own `messages` list, runs its own loop (capped at 30 turns), and returns the last text block.
- The parent registers `task` alongside its base tools via the same `TOOL_HANDLERS` dispatch map — no special wiring needed.
- The subagent gets the 5 base tools (`bash`, `read_file`, `write_file`, `edit_file`, `glob`) but **not** `task`, preventing recursive delegation.

### One-Line Insight
> *"Message isolation, not process isolation"* — the subagent cleans up context noise while still sharing the real workspace.
